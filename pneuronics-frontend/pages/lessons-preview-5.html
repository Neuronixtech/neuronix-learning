Linear Algebra Intuition

See what vectors, matrices, and dot products actually mean — geometrically and in code.

the problem

Open any ML paper. Within the first page you'll see vectors, matrices, dot products, and transformations. Without linear algebra intuition, these are just symbols. With it, you can see what a neural network is actually doing — moving points around in space.

the math
magnitude(v) = √(v₁² + v₂² + ... + vₙ²) dot(a, b) = Σ aᵢ × bᵢ cosine_sim(a, b) = dot(a,b) / (|a| × |b|)
The dot product measures how much two vectors point in the same direction. Cosine similarity normalises it to [−1, 1] so magnitude doesn't distort the comparison.
concept 1 — vectors are points and directions

A vector is coordinates in space

A vector is a list of numbers — each number a coordinate. In AI, vectors represent everything: a word as 768 numbers, a user as preference scores, an image as pixel values.

word → 768 numbersimage → millions of pixelsuser → preference scores
concept 2 — matrices are transformations

A matrix moves points in space

Multiply a vector by a matrix and you get a new vector — rotated, scaled, or projected. Every neural network layer is a matrix multiplication.

Neural net weights
Matrices that transform input into output at each layer
Attention scores
Matrices deciding which tokens to focus on
Embeddings
Matrices mapping tokens into vector space

vectors.py
import math

def dot(a, b):
    return sum(x*y for x,y in zip(a, b))

def magnitude(v):
    return math.sqrt(sum(x**2 for x in v))

def cosine_sim(a, b):
    return dot(a, b) / (magnitude(a) * magnitude(b))

a, b = [1,2,3], [4,5,6]
print(f"dot     = {dot(a,b)}")
print(f"|a|     = {magnitude(a):.4f}")
print(f"cos_sim = {cosine_sim(a,b):.4f}")

💡Cosine similarity = 0.97 means a and b point nearly the same direction. This is exactly how semantic search, RAG, and recommendation engines find relevant results — high cosine similarity = relevant.

Matrix Multiplication

The single operation that runs inside every neural network layer — forward pass, attention, embeddings.

the problem

Every PyTorch line that says x @ W is a matrix multiplication. Without understanding what it does geometrically — how it transforms input to output — you can't debug shapes, design architectures, or reason about what your model learns.

the math
C = A @ B where Cᵢⱼ = Σₖ Aᵢₖ × Bₖⱼ A ∈ ℝᵐˣⁿ, B ∈ ℝⁿˣᵖ → C ∈ ℝᵐˣᵖ (m×n) @ (n×p) → (m×p) — inner dims must match
Each output element Cᵢⱼ is the dot product of row i of A with column j of B. A (3×4) @ (4×5) gives a (3×5). This is why a layer with 512 inputs and 256 outputs needs a (512×256) weight matrix.
concept 1 — what the shapes mean

Input × Weights = Output

A linear layer is just: output = input @ W + b. The weight matrix W transforms every input row into a new space. The shape of W controls what the transformation does.

Input x
(batch_size × 512) — one row per sample
Weights W
(512 × 256) — maps 512-dim to 256-dim
Output
(batch_size × 256) — compressed representation
concept 2 — why it's not commutative

AB ≠ BA — order matters

Unlike scalar multiplication, matrix order changes the result entirely. This is why PyTorch raises shape errors — you can't flip the operands. The transformer's QKᵀ has to be Q times Kᵀ, not Kᵀ times Q.

the code
matmul.py
import numpy as np

def matmul(A, B):
    m, n = len(A), len(A[0])
    n2, p = len(B), len(B[0])
    assert n == n2, f"Shape mismatch: ({m},{n}) @ ({n2},{p})"
    C = [[0]*p for _ in range(m)]
    for i in range(m):
        for j in range(p):
            C[i][j] = sum(A[i][k]*B[k][j] for k in range(n))
    return C

A = [[1,2],[3,4]]
B = [[5,6],[7,8]]
print(np.array(matmul(A, B)))
# Then verify with numpy
print(np.array(A) @ np.array(B))
output
hand-built =[[19 22] [43 50]]
numpy =[[19 22] [43 50]]
💡The O(mnp) cost — multiply a (2048×4096) by (4096×4096) matrix costs 34 billion ops. This is why transformer inference is slow and why GPUs exist: they parallelise thousands of these simultaneously.

Gradient Descent

The algorithm that trains every neural network — written in 10 lines before any optimizer gets imported.

the problem

Every time you call optimizer.step(), gradient descent is running. Without understanding the update rule — what a gradient is, why we subtract it, what the learning rate does — you can't tune training, diagnose divergence, or understand why Adam beats SGD.

the math
θ ← θ − α · ∇L(θ) ∇L(θ) = ∂L/∂θ (gradient of loss w.r.t. params) α = learning rate (step size) L(θ) = loss function (what we minimise)
The gradient points uphill. Subtracting it moves us downhill. The learning rate controls how big each step is — too large and we overshoot, too small and training takes forever.
concept 1 — what a gradient is

The gradient is a slope in every direction

For a function with one parameter, the gradient is just the slope. For a model with millions of parameters, it's a vector — one slope per parameter. PyTorch's autograd computes all of them at once via the chain rule.

∂L/∂W — how much loss changes if W changesnegative gradient = direction of steepest descent
concept 2 — learning rate intuition

Step size determines everything

α = 0.1 takes large steps — fast but may overshoot. α = 0.0001 takes tiny steps — stable but slow. Most practitioners start at 3e-4 (the "Karpathy constant") and tune from there.

α too large
Loss bounces or diverges. Overshoots the minimum.
α just right
Loss decreases smoothly. Converges to a minimum.
α too small
Takes thousands of extra steps. Gets stuck in local minima.

gradient_descent.py
# Minimise L(w) = w² — simplest possible loss
w = 2.0     # start away from minimum w=0
lr = 0.1    # learning rate

for step in range(20):
    loss = w**2
    grad = 2 * w        # ∂(w²)/∂w = 2w
    w = w - lr * grad   # gradient descent update
    if step % 5 == 0:
        print(f"step {step:2d}: w={w:.4f}  loss={loss:.6f}")
output
step 0:w=1.6000 loss=4.000000
step 5:w=0.3277 loss=0.419430
step 10:w=0.0671 loss=0.017592
step 15:w=0.0138 loss=0.000738
💡This 6-line loop is conceptually identical to what PyTorch runs with loss.backward(); optimizer.step(). The only difference is that autograd computes gradients for millions of parameters at once, and Adam adapts the learning rate per-parameter.

Probability & Entropy

Cross-entropy loss, softmax, and KL divergence — explained from first principles.

the problem

Every classification model outputs probabilities. Every language model picks the next token by sampling a probability distribution. The training loss is cross-entropy. Without understanding what entropy measures and why we minimise cross-entropy, loss curves are just numbers.

the math
H(p) = −Σ p(x) log p(x) entropy H(p,q) = −Σ p(x) log q(x) cross-entropy KL(p ∥ q) = H(p,q) − H(p) how far q is from p softmax(xᵢ) = exp(xᵢ) / Σⱼ exp(xⱼ) outputs sum to 1
Entropy measures how uncertain a distribution is. Cross-entropy measures how well distribution q approximates the true distribution p. Minimising cross-entropy loss = making your model's distribution q match the true distribution p.
concept 1 — what entropy means

Entropy = average surprise

A fair coin has entropy 1 bit — maximum uncertainty. A coin that always lands heads has entropy 0 — no surprise. A language model that always predicts "the" has near-zero entropy but terrible cross-entropy when the next token is "photosynthesis".

H = 0
Certain outcome. Model always predicts one token. Useless.
H = 1 bit
50/50 split. Maximum uncertainty for binary choice.
H = log(V)
Uniform over vocabulary. Model learned nothing.
the code
entropy.py
import math

def entropy(p):
    return -sum(px * math.log2(px) for px in p if px > 0)

def cross_entropy(p, q):
    return -sum(px * math.log2(qx) for px, qx in zip(p, q) if qx > 0)

def softmax(x):
    e = [math.exp(v) for v in x]
    s = sum(e)
    return [v/s for v in e]

logits = [2.0, 1.0, 0.1]          # raw model outputs
probs  = softmax(logits)            # convert to distribution
target = [1, 0, 0]                 # true class = index 0
print(f"softmax : {[f'{p:.3f}' for p in probs]}")
print(f"entropy : {entropy(probs):.4f} bits")
print(f"xent    : {cross_entropy(target, probs):.4f}")
output
softmax :['0.659', '0.242', '0.099']
entropy :1.2171 bits
xent :0.4170
💡GPT-4's perplexity on English text is ~10 — it's mildly surprised by each word. A random model over a 50,000-word vocabulary would have perplexity 50,000. The gap is what 175 billion parameters of training buys.

Eigenvalues & PCA

Directions a matrix doesn't rotate — and how they power dimensionality reduction, PageRank, and spectral clustering.

the problem

PCA appears in every ML workflow: reducing feature dimensions before training, visualising high-dimensional embeddings with t-SNE/UMAP, compressing representations. It's always described as a black box. It has exactly one mathematical step: find the eigenvectors of the covariance matrix.

the math
Av = λv eigenvector equation A = UΣVᵀ SVD — generalises to any matrix C = XᵀX / (n-1) covariance matrix of centred data PCA: top k eigenvectors of C = k principal components
An eigenvector v of matrix A is a vector that A only scales (by λ), never rotates. The covariance matrix C encodes how features vary together. Its eigenvectors are the directions of maximum variance — the principal components.
concept 1 — geometric intuition

Eigenvectors are invariant directions

Apply matrix A to a random vector and it rotates and scales. Apply it to an eigenvector and it only scales — the direction stays fixed. These invariant directions reveal the structure of A: how it stretches space, what its "grain" is.

concept 2 — PCA step by step

Find the directions of maximum variance

Centre the data, compute the covariance matrix, find its eigenvectors sorted by eigenvalue. Project data onto the top k eigenvectors. That's PCA — no black box, just three matrix operations.

Step 1
Centre data: X_c = X − mean(X)
Step 2
C = X_cᵀ X_c / (n−1) — covariance
Step 3
Top k eigenvectors of C = principal components
the code
pca.py
import numpy as np

def pca(X, k=2):
    X_c = X - X.mean(axis=0)           # centre
    C   = X_c.T @ X_c / (len(X) - 1)   # covariance
    vals, vecs = np.linalg.eigh(C)      # eigenvectors
    idx = np.argsort(vals)[::-1][:k]   # top k
    return X_c @ vecs[:, idx]            # project

np.random.seed(0)
X = np.random.randn(100, 10)  # 100 samples, 10 features
X_2d = pca(X, k=2)            # reduce to 2D
print(f"Input shape  : {X.shape}")
print(f"Output shape : {X_2d.shape}")
print(f"Variance kept: {X_2d.var(axis=0).sum()/X.var(axis=0).sum():.2%}")
output
Input shape :(100, 10)
Output shape :(100, 2)
Variance kept:22.14%
💡sklearn's PCA does exactly this — you can now diff your implementation against it. The same eigenvector logic underlies PageRank (eigenvector of the web graph), spectral clustering, and why covariance matrices are always eigendecomposable.
